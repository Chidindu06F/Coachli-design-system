# Building the Coachli dashboard

A guide for developers rebuilding the Coachli dashboard with this design system.

## What you get

| | Where |
| --- | --- |
| Components and tokens | `@chidindu06f/coachli-react` and `@chidindu06f/coachli-tokens` (install steps in the [README](README.md)) |
| Live component docs | Storybook: https://chidindu06f.github.io/Coachli-design-system/ |
| Screens to build | Figma: [Coachli](https://www.figma.com/design/toCoFh482t5Ho9OU7it9lA/Coachli), one page per menu item. Each page has grey sections per context, with black labels above each screen |
| Component specs | Figma: [COACHLI DESIGN SYSTEM](https://www.figma.com/design/fNq8x9qbF4yYA6ixgwdGVR/COACHLI-DESIGN-SYSTEM). Dev Mode shows the matching React code |

## Setup

```tsx
// main.tsx: once, at the top of the app
import '@chidindu06f/coachli-tokens/css';
import '@chidindu06f/coachli-react/styles.css';
import '@fontsource/inter/400.css';
import '@fontsource/inter/600.css';
import '@fontsource/inter/700.css';
```

- **Themes:** set `data-theme="light" | "dark" | "system"` on `<html>`. Every component switches by itself.
- **Your own CSS:** use the tokens (`var(--halo-text-secondary)`, `var(--halo-spacing-md)`), never hex values, or dark mode breaks.
- **Breakpoints:** `--halo-grid-*` tokens change at 600px (tablet), 1024px (desktop) and 1440px (wide).

## How a screen maps to code

Read a screen from its Figma layers: almost everything is a library component instance whose name matches the React component.

| In Figma | In code |
| --- | --- |
| Sidebar (Layout=Expanded / Collapsed) | `<Sidebar header={logo} beforeFooter={roleSwitch} footer={…} collapsed>` with `NavItem` children |
| Sidebar *Show footer* | `beforeFooter`: the Coach / Customer role switch (a `SegmentedControl`) |
| Sidebar *Show report a bug* / *Show log out* | `NavItem`s in `footer`. What's new and Help and resources are not in the sidebar: What's new lives in the Notifications drawer (bell); Help and resources is a row on Home, and its full page (View all) has a back arrow to Home |
| Text component (Size, Weight, Colour) | `Text` |
| Card, List, List item, Badge, Tag, Tabs, Table cells | Components with the same names |
| Modal / Drawer inside an Overlay | `Modal` / `Drawer` (they bring their own overlay) |
| Toast | `useToast()` inside a `<ToastProvider>` at the app root |
| Tour step | `Tour` |
| Plain frames | Layout only: flex/grid using the spacing tokens |

## Product rules (from design reviews)

- **Dev notes in Figma:** behaviour that a screen can't show (search timing, retention, exports) is written in a yellow **Dev note** card to the right of the screen it explains. Read them before building.

- **Page scrolling (desktop):** the dashboard is an app shell exactly the height of the window (`100vh`). The window never scrolls. The sidebar is full height; the page header (greeting, time zone, bell, Create, avatar) stays pinned at the top; only the body below it scrolls (`overflow-y: auto`), with 60px (`--halo-spacing-11`) of space after the last section. Figma shows this on *Home: scroll behaviour (prototype)*. Other screens are drawn at full height only so the whole design is visible.
- **Don't clip focus rings:** containers only clip when they scroll or truncate (e.g. the sideways Help cards, scrolling tab rows). Everything else uses `overflow: visible` so input focus rings aren't cut. The Modal body is the scroll area, so it has 4px of inner padding (the modal's sides are 20px and the header/footer sides 4px, so content still sits 24px in). Popover, Radio group, Table cell, Segmented control and Stepper slots don't clip.
- **Modals:** never taller than 720px or the window. Long content scrolls inside the modal while the title and buttons stay visible (built into `Modal` from 0.2.6).
- **Copy length:** empty-state descriptions and any helper/supporting text fit in **two lines** at most. Short, scannable sentences.
- **List alignment:** List item has **no side padding** (0 left/right, vertical padding unchanged), so rows line up with their heading, progress bar or anything else in the same container. The container holding the rows gives the inset: **12px left/right, 8px top/bottom** (the List Card style uses the same; plain list frames and mobile lists that replace tables get it too), never the row. Hover and selected backgrounds fill the row as is. `List.module.css` still uses `--pad-x` and needs updating to match.
- **Side drawers** (desktop) are **560px** wide (Drawer Size=Large).
- **Payout account (connect and update):** never a modal or sheet; the form replaces the Payout settings card inline (desktop and mobile). New coaches see **Connect bank account**; once connected the card shows the account and **Update account details**. The update form shows **Current details** (the connected account) on top; the code step shows **New details**. Steps, each revealing the next field: **Country** (Select with flag) → **Bank** (list depends on the country) → **Account number**, then **Verify details**. When verified, the field turns Success and its hint shows the account name ("Account name: JOHN DOE"), and the button becomes **Save changes**. Saving sends a 6-digit code to the coach's email (toast "Code sent to j•••@email.com") and the card becomes **Confirm your new account**: new account summary, "Wrong details? Edit" (only Edit is a link), Verification code (6), "Resend code in 0:15" countdown that turns into "Didn't get a code? Resend code", and **Verify and save** (disabled until all 6 digits). Success returns to Payout settings with the new account and a toast ("Bank account updated" / "Bank account connected"). Cancel returns to Payout settings. The Withdrawal page's Update link and the Withdraw funds modal's Change link open the same form.
- **Settings › Account & security:** two cards. **Login details** (no subtitle) lists Email and Password as rows (value underneath, secondary **Change** button). **Two-factor authentication** has the title, one line of help and a switch. When it's on, the card adds **Method** (Authenticator app or Email, Change) and, for the authenticator app only, **Recovery codes** (Regenerate). No step counters anywhere in these flows.
- **Change email / password:** Change turns the row into an inline form inside the Login details card, with no modal for the form. Email has **New email address** with Cancel / Continue; Password has **Current password**, **New password** and **Confirm new password** (EyeSlash toggles) with Cancel / Save. The primary button is disabled until the fields are filled. It then sends a code to the **current** email and opens **Check your email** ("We sent a 6-digit code to … Enter it to confirm your new email/password.") with the code input, "Didn't get a code? Resend in 0:22" then a Resend code link, and Back / Verify. Verify saves the change, closes the form and shows the toast "Email updated" / "Password updated". The Password row then reads "Last changed just now".
- **Turn on 2FA:** turning the switch on opens a modal "Turn on two-factor authentication": choose **Authenticator app** ("Recommended. …") or **Email**, shown as Radio cards (one bordered card per option, Selected state on the picked one). Next is disabled until one is picked.
  - **Authenticator app:** Next closes the modal and opens the **Authenticator app** drawer (560px; bottom sheet on mobile). It has the QR code, the setup key with Copy, and the 6-digit code input. **Verify code** is disabled until all 6 digits are in; a wrong code shows the error digits and an inline error alert. After verifying, a modal **Save your recovery codes** shows the 10 codes, "You'll only see these codes once", Download / Copy and an "I've saved my recovery codes" checkbox that enables Done. Done turns 2FA on with the toast "Two-factor authentication is on".
  - **Email:** Next opens the modal **Check your email** ("We sent a 6-digit code to …"), with the code input and "Didn't get a code? Resend in 0:22", which becomes a Resend code link when the timer ends. Back / Verify; Verify turns 2FA on with the same toast. No recovery codes.
- **Turn off 2FA:** switching it off opens **Confirm it's you** (heading "Turn off two-factor authentication", "Your account will only be protected by your password…") with the code input. Cancel / **Turn off** (destructive, disabled until 6 digits). Then the toast "Two-factor authentication is off".
- **Change 2FA method:** Method › Change opens **Confirm it's you** ("Change your two-factor method") with the code input. Cancel / Continue; Continue opens the choose-method modal titled **Change two-factor method** with the current method selected, and the setup flow runs again.
- **Regenerate recovery codes:** Recovery codes › Regenerate opens **Confirm it's you** ("Regenerate recovery codes", "Enter the code from your authenticator app to continue.") with the code input. Cancel / Continue (disabled until 6 digits). Then the modal **Save your new recovery codes** ("Your old codes no longer work…"), with the same codes, warning, Download / Copy and checkbox-gated Done as setup. Done shows the toast "New recovery codes created".
- **Settings › KYC verification** (Figma page "Settings / KYC verification"): one card, **Verify your identity**, with a two-step Stepper (Basic details › Documents).
  - **Basic details:** Full legal name (hint "As it appears on your ID."), Business name (optional), Services you offer (textarea), Social media or website (platform select + URL, **Add link**), Email address, Date of birth + Gender (side by side on desktop), Residential address, Country of residence (with flag) + Postal code, then **Next**.
  - **Placeholders are examples**, written as "e.g. …" sample answers, not instructions ("e.g. I offer 1:1 career coaching for new managers and run a monthly leadership workshop.").
  - **Social link platform:** the select shows the platform's brand logo (DS Logos/Social). The list is LinkedIn, Instagram, X, Facebook, TikTok, YouTube, Threads, and Website (Globe icon), with the chosen one Selected. **Add link** adds another platform + URL row; every row gets a remove button (ghost icon button, red Trash) once there is more than one. On mobile the platform select shows only the logo and caret, so the URL has room. On mobile the stepper is the Compact variant: "Step 1 of 2", the step title, "Next: Documents" (shown on step 1 only, since step 2 is last), and a 2-segment bar.
  - **Documents:** four File upload dropzones, each with a one-line description: Proof of address, Government-issued ID, Selfie holding your ID, Business registration (optional). Choosing upload opens a guide modal (header icon, 3–4 short tips, Cancel / Choose file or Take selfie) before the file picker. Uploaded files show as File items (name, size, Uploaded, delete). A consent checkbox enables **Submit**; Back returns to Basic details.
  - **After submitting:** the **Submission received** modal, then the card shows an Empty state with an icon avatar: **Verification in progress** (24–48 hours, email when done), **You're verified**, or **We couldn't verify your identity** with the specific reason and **Try again**. The reason is shown only on that unsuccessful state; Try again reopens the filled form with no extra alert. On mobile the same screens stack, and modals are bottom sheets.
- **Image upload** (DS, File upload page; not in the React package yet): a compact control for profile pictures and logos. An Avatar (64px Default, 48px Compact) with a User (Person) or Buildings (Business) icon when empty. **Default** adds the title "Upload image" and the hint "Min 400×400px, PNG or JPEG". When empty it shows **Upload**; once uploaded, the image shows with **Change** (secondary) and a **Remove** icon-only ghost button with a red Trash icon (icon/negative). Use Compact where space is tight (forms, mobile).
- **Breadcrumbs go under the page heading**, never above it. Because the breadcrumb is how you go back, there's no back arrow next to the heading.
- **Create-page preview (invoice, 1:1 session, every offering):** a bordered card (16px padding, 16px radius) whose header is "Preview" + a **Draft** badge + an icon-only open button (ArrowSquareOut) on the right. The card shows the compact (mobile-width) preview. The open button goes to a full **Preview** page inside the dashboard (heading, breadcrumb, **Back to edit**), which shows the desktop layout on a grey canvas. For a session, that's the public booking page: cover and description on the left, booking, share and reviews on the right.
- **Create a 1:1 session (chosen flow: steps):** a full page with heading, breadcrumb and a Compact stepper ("Step N of 4", "Next: …"). Top-right actions are Cancel / Back, **Save as draft**, and Next, which on the last step becomes **Create session**. Step 1, General information: collapsible sections for Session details (open; it also holds the cover image upload, under the duration), Pricing, Availability, Location and Redirect after purchase. Step 2: Checkout questions. Step 3: Automations. Step 4, the last: Settings. Session bundles follow the same four steps. Leaving without saving asks "Save as draft" / "Keep editing". Create session shows the Session published modal with confetti, then the sessions list with a toast. The old checklist and options A/B are on the Archive page.
- **Create flows on mobile:**
  - Full screen. The top bar has a close button (Cancel), the title and an eye icon that opens the full preview.
  - The compact stepper shows "Step N of 3" with "Next: …".
  - A bottom bar is pinned with the actions: step 1 has Save as draft and Next. Later steps add an icon-only Back button. The last step's button is Create session or Create bundle. Edit uses Next and Save changes.
  - Rows that sit side by side on desktop stack on mobile: custom duration, the bundle's number of sessions, interval and length, and each pay-what-you-want currency (currency on top, then minimum and suggested price side by side).
  - The full preview stacks the session details above the booking calendar. Leave without saving and Session published are centred modals.
- **Create invoice uses the same steps:**
  - Step 1 Content has Invoice details, From, Bill to, Items, and Note and attachment.
  - Step 2 Customise is one Branding section, open by default, holding Logo, Template, Accent colour and Font, each with its own label.
  - Each is a collapsible section on one page, with the live invoice preview on the right.
  - Actions: Cancel or Back, Save as draft, then Next or Publish invoice. Leaving asks "Leave without saving?".
  - On mobile, items stack as cards (name, then quantity, unit price and discount, then the amount).
  - The old checklist flow is on the Archive page.
- **Price rows:**
  - The first currency row is labelled "Default price" ("Default minimum price" for pay what you want), with no Default badge.
  - Other rows end with a 20px bin button, centred on the field. The default row keeps an empty 20px slot in the same place, so every row's fields line up in columns. Minimum and Suggested price split the row evenly on desktop.
  - On mobile, pay what you want keeps Minimum and Suggested price on one line: Suggested is 110px wide and Minimum fills the rest.
- **Bundles, duplicate and edit use the same steps:** **Create a session bundle** has the same three steps; its first section is Bundle details: Bundle name, Bundle description, then a row of **Number of sessions**, **Booking interval** and **Each session lasts**. The last step's button is **Create bundle**, and the preview shows "4 sessions · 60 minutes each". **Duplicate** in the row ⋮ menu shows a "Session duplicated" toast, then opens the copy on step 1 titled "<name> (copy)" with a Draft badge. **Edit** opens the same steps with the session name as the heading and a Published badge, and **Save changes** in place of Save as draft. The old checklist versions of edit and duplicate are on the Archive page. In Figma, both flows start from the row ⋮ menu open with Duplicate or Edit hovered.
- **Step intros:** Checkout questions starts with "We collect first name, last name and email address by default. You can add up to 10 more questions." Automations starts with "Send emails automatically when someone books, like a welcome note or a reminder before the session." Both are small secondary text at the top of the section.
- **1:1 sessions has two kinds:** a **one-off session** and a **session bundle**. Use "One-off session" in menus and labels, never "1:1 session" for the single kind.
- **Step 1 section states (Figma, 1:1 sessions section):** one row per section. Each state is a full step 1 screen with that section open and the others closed, labelled with the state. Session details: empty, filled, name missing. Cover image: empty, drag over, uploading (progress and cancel), uploaded (drag handle to reorder, delete), upload failed (retry), file not supported, image limit reached (upload area disabled). Pricing: free, single fee, single fee with several currencies (the first is Default, the others can be deleted, and an **Add currency** secondary small button with a plus icon below), pay what you want (Minimum price and Suggested price per currency), with several currencies, price error, minimum above suggested. Availability: schedule chosen, no schedule chosen (error). Location ("Where will this session happen?"): options are Coachli video, Google Meet, Zoom, Custom meeting link and Phone call (shown open in Figma). Google Meet needs Google Calendar connected and Zoom needs Zoom connected; if not, a warning Alert under the select says "Connect your Google Calendar to use Google Meet as the location." or "Connect your Zoom account to use Zoom as the location." with a Connect Google Calendar or Connect Zoom action. A one-off session has no in-person option; that is only for live events. Phone call asks for nothing from the coach: the customer gives their phone number at checkout. The preview shows the chosen location. Redirect after purchase: options are None, Telegram and Custom URL. States: none, options open, custom URL, invalid URL, Telegram not connected ("Connect your Telegram account to send customers to a group after they pay." with a Connect Telegram button), Telegram connected (Telegram group select with the hint "Add the Coachli bot to your Telegram group chat to select it here."), no groups yet, group options and group selected. Cover image drag over shows an image being dragged onto the drop area.
- **Figma order (1:1 sessions page):** one section in the order a new coach meets it: empty state and Create menu, create a 1:1 session, session published, create a session bundle, upcoming sessions, past sessions, row actions, duplicate, edit, then sales and insights.
- **Selectable lists:** the List item has 0 side padding, and the container gives the inset (12px sides, 8px top and bottom). In lists whose rows can be hovered or selected, such as the Messaging conversation list and pickers, each row gets 8px side padding (`spacing-4`) and the container drops to 8px. That way the highlight never touches the avatar, and the text still lines up with the search field above. In code, this is a padding option on `ListItem` for selectable lists.
- **Chat bubbles:** received bubbles use `surface/minimal` with `text/primary`. Sent bubbles use `surface/chat-sent` with `text/chat-sent` (slate, with light and dark values); file sizes and times stay `text/secondary`. Don't use teal or lilac for bubbles.
- **Modals and sheets in Figma:** every modal and sheet is drawn at full height inside its screen, so all its content is visible. A dev note beside the flow gives the real behaviour: the modal is at most 720px tall (or the window), the header and footer stay fixed, and only the body scrolls.
- **1:1 session Settings switches** (Hide from your profile page, Request customer's phone number) have labels only, with no description line.
- **Select width:** fit the select to its content when the options are short and known: currency, date range filters (This week, All time, Last 90 days), page size, social platform. Selects in one column share a width so the rows line up; currency fields in forms are 120px. Keep a select full width when the value is long or written by the coach (schedule, location, time zone, redirect, font), or when it is stacked with full-width inputs. In React, give the `Select` wrapper the width; the component fills it.
- **Price and currency are one field:** the price Input has a select prefix (`InputAffixSelect` in React, Input affix Kind=Select in Figma) showing the flag and currency code. There's no separate Currency select. For pay what you want, Minimum price carries the currency, and Suggested price is a plain input beside it (stacked on mobile).
- **Social links (KYC) use the same select prefix:** the link field has the platform picker inside it, showing the logo only (Input affix Icon on, Show label off; `InputAffixSelect` with `showLabel={false}`). The Select prefix has one square Icon slot for flags, logos and icons; in Figma, flags there come from "Flags (square)". For a plain icon in a field, like a user icon on a name field, use the Input's leading icon, not a prefix. The open list shows logo and name. The remove button is the neutral compact bin, not red.
- **Currency selects show the country flag** before the code (US for USD, NG for NGN, GB for GBP), from the DS flag set; pass it as the `Select` option `icon`. "All currencies" has no flag.
- **Red text matches the red icon:** error messages under fields, destructive menu items (Delete) and other error text use `state/error/primary` (#E93544), the same red as `icon/negative`. The dark red `state/error/contrast` is only for text on a light red fill (Alert, error Badge, Result).
- **Error messages state the problem only:** for example "Enter a valid link.", with no sample value or extra explanation. Examples belong in placeholders, not in errors.
- **Step 1 option lists (to confirm with product):** Session duration (confirmed): 15, 30, 45 or 60 minutes, or Custom. Custom shows a "Custom duration (in minutes)" number input beside the select. Schedule: the coach's schedules (e.g. Weekday sessions, Weekend sessions, Evenings only). Currency: USD, NGN, GBP, each with its flag. Bundle number of sessions is a number input, not a dropdown. Booking interval: 1 day, 3 days, 5 days, 1 week, 2 weeks (confirmed). Each session lasts uses the duration list.
- **Dropdowns in Figma:** every select shows its option list open in at least one screen, so the options are documented.
- **Field side padding is content-based:** in Input, Select and Combobox, an icon, flag, avatar, caret or tag sits 6/8/12px (sm/md/lg) from the edge, and text sits 10/12/16px. The components do this on their own; don't override the padding on a screen.
- **Flags and social logos:** use the flags and logos as exported from the design system. Flags have a 1px light-grey outline outside the artwork (`border/secondary`) so light flags show on white; in code, use `outline: 1px solid var(--halo-border-secondary)` (outline sits outside, like Figma) and don't shrink the flag for it. Social logos are in brand colour, Instagram included (its gradient, not black).
- **Public profile builder (Figma: Public profile page):** the builder keeps the existing flow and copy, rebuilt with DS parts. Content / Theme / SEO and sharing is a `ButtonGroup` (the active one looks pressed). Each block is a collapsible section; movable blocks have a drag handle, a show/hide `Switch` and a delete icon button. Footer and Header can't be moved or deleted. "Add a block" opens a picker of block types above the button. The preview on the right is the coach's public page in their theme: it scrolls on its own and keeps the theme's styles, not the dashboard's. Social links use the same logo-only platform picker as KYC (`InputAffixSelect` with `showLabel={false}`), each platform with its own placeholder (URL, username, phone number or email).
- **Create menu icons:** each item in the Create menu has its own coloured icon in a soft glossy style (pastel gradient fill, coloured outline). They are artwork, not design system icons: export them as SVG from the "Create icon" component in Figma (Components page) and show them at 24px. Don't recolour them with the text colour. The artwork comes from Kubai Icons (MIT): video-call, layers, mic, file-down, repeat, briefcase, invoice, badge-percent, mail with a bolt badge, graduation-cap. Create menu items are plural: One-off sessions, Session bundles, Live events, Digital products, Subscriptions, Services, Invoices, Discounts, Email automations.
- **Coachli video (Figma: Scheduling / Coachli video):** our own video calls for 1:1 sessions and live events, designed mobile first, with a desktop screen for every mobile state. The whole experience is dark (`data-theme="dark"`): waiting room, call and end screens. The waiting room and end screens sit on a soft teal glow with rings and grain. The Coachli mark is at the left of the call's top bar. The call opens in a new browser tab so the dashboard stays open. People join straight from the waiting room; there is no admit step. If camera or mic access is blocked, they can still join with both off. Mobile controls: mic, camera, raise hand, more, leave; More opens a menu with share screen, recording, reactions, layout, speaker and settings; attendees and chat open as bottom sheets. Desktop puts every control in one bar (More holds Change layout and Settings) and opens chat or attendees as a side panel, one at a time. Every icon button shows its name on hover, and uses the pressed style when it is on or open. Settings has Camera, Microphone and Speaker pickers only; changes apply at once. The host sees Record, Mute all, the person menu (Mute, Lower hand, Remove from call) and End call for everyone. Live events can have a co-host, chosen when the event is created (nobody can be made co-host during the call); a co-host can do everything the host can. 1:1 sessions have no co-host. Customers see none of these. Everyone sees the REC badge while recording, and the recording lands in Customers › Recordings after the call. The person speaking gets a green outline.
- **Edit invoice:** "Edit" (invoice list row menu, or the Edit button on Invoice details) opens the create form in edit mode, filled with the invoice. Header: the invoice name with its status badge, breadcrumb Invoices / {number}, then a secondary "Sales and insights" button (for now it goes to the Invoice details page) and a ⋮ menu with Copy link, Duplicate and Archive. Bottom bar: Cancel, Next and Save changes on step 1; Back and Save changes on step 2. Saving returns to Invoice details with an "Invoice updated" toast. A paid invoice cannot be edited: it has no Edit button or menu item. On mobile the title is "Edit invoice" and the bottom bar has Next and Save changes.
- **Invoice attachment hint:** under the attachment upload: "e.g. Terms and conditions, a contract, a project brief, etc."
- **Invoice templates (Figma: "Invoice layout" on the Components page):** six templates replace the old five: Headline, Sign-off, Side rail, Banner, Framed and Centred (Centred replaced Split, which was only a colour change of Side rail). Every template is built with auto layout (header, details row, parties, item table, summary, note, footer), so the structure in Figma is the structure to build; only the PAID stamp floats. Each has a large "Invoice" in the display font (New Spirit), and uses the coach's accent colour for its rail, banner, frame or tinted panel, the item table rule, the pay link and the amount due. The logo is optional: show it in the logo slot only when the coach uploaded one, and leave the slot out otherwise. The template picker shows the blank version (grey placeholder bars, dashed logo slot); the live preview and the sent invoice show the filled version. A paid invoice shows the red PAID stamp (rotated, outlined) beside the totals. The footer says "Powered by" with the Coachli logo image, not typed text.
- **Create flows, action bar:** on desktop the step actions (Cancel or Back, Save as draft, Next or the final action) sit in a bar fixed to the bottom of the main area, left-aligned, Medium buttons, with a top border. The bar is sticky. It stays in place while the form scrolls, so give the form bottom padding equal to the bar's height plus 24px. The page header keeps only a Small secondary "Watch demo video" button beside the account menu; the demo video card inside the form is gone. "Watch demo video" opens the YouTube video in a modal on Coachli with the embedded player, the same modal as Help and resources (title, player, Close). It never sends the coach to YouTube. Closing the modal stops the video. This applies to invoices, one-off sessions and session bundles. Mobile already has its bottom bar (Save as draft, Next) with Cancel as the close icon in the top bar.
- **Invoice Bill to, customer search:** the Customer name field searches the coach's customers as they type. Results open in a Menu under the field, as wide as the field: each row has the avatar, name and email. Picking one fills the name and email (and the billing address if we have it). The last row, under a divider, is `Add "<typed text>" as a new customer`; picking it keeps the typed name and leaves email and address for the coach to fill. Bill to stays optional.
- **Live events page:** the page a coach lands on from the sidebar, built like the 1:1 sessions page. **Empty:** "No live events yet" with a "Create live event" button (also in the header; it goes straight to the create flow, there is no menu). **With events:** three tabs with counts: Upcoming, Past and Co-hosted. Co-hosted lists events where the coach is another coach's co-host ("Hosted by …", Join event); when there are none it says "No co-hosted events yet. When another coach adds you as a co-host, their event shows up here." An event starting soon shows on top with "Starts in …", Copy link and Start event. Rows show time, duration, location and how many registered ("40 of 50 registered" when attendees are limited). There is no table of all events under the tabs. Every row reads the same way: time · duration · location · how many registered (Upcoming) or attended (Past), and nothing else (no "Completed" or "Cancelled by you").
- **Live events, actions on the page:** each event row has View details and a ⋮ button; the ⋮ opens a menu with Edit, Sales and insights, Copy link, View event page, Hide from profile, Duplicate and Delete, each with its toast ("Link copied", "Hidden from your profile", "Event duplicated", "Event deleted"). Delete asks "Delete {event}? Customers won't be able to register for it any more." **View details** opens the event drawer: price, date, time, location, Registered ("24 of 50"), Co-hosts, Event link, Created on, Type and the Attendees list (name and email), with Cancel event and Edit event. Cancel event asks for a reason and tells everyone who registered. **After Create event:** the "Event published" modal with confetti ("Your event is live!", the link and share buttons), then the Live events page with an "Event published" toast. Edit event opens the same form with Cancel, Next and Save changes in the bottom bar only. The header, beside the avatar, has a secondary "Attendees and insights" button and a ⋮ menu with Copy link, View event page, Hide from profile, Duplicate and Delete (Edit session is the same, with "Sales and insights"). A duplicate is a draft named "{event} (copy)"; after duplicating, the list shows it under the original. Leaving the form asks "Leave without saving?".
- **Live events on mobile:** every create state has a mobile screen. Fields that sit side by side on desktop stack (date, time, duration; co-host first name, last name, email with the bin under them; currency prices). The bottom bar has Back (from step 2), Save as draft and Next / Create event.
- **How the Figma screens are grouped:** on each page, screens sit in rows by feature, with a wide header naming the group ("Step 2 states: Checkout questions") and a label over each screen. Inside a group the order is always: Empty state, then the state while something is being added or a dropdown is open, then filled, then errors. Build each group as one feature.

Create new and Edit open a drawer (a full-height sheet on mobile) with the email fields, trigger, offerings and timing. All lists every automation with Add / Added.

Breadcrumb: Live events / {event} / Attendees and insights. Two metric cards (Attendees, Total earned), then the attendee table (Attendee, Email, Payment reference, Amount, Registered on) with search and Export CSV. - **Live event location, Physical location:** choosing it shows, straight under the select with no note or banner, a "Venue address" search field (placeholder "e.g. Radisson Blu, Lagos", search icon on the right) and a switch "Only show to registered attendees". - **Cover image, Canva templates:** under every cover image upload (one-off sessions, session bundles, live events, and later offerings, but not invoices) there is a link: "Get free Canva templates for your cover image". - **Dropdowns and popovers:** no arrow, soft shadow (`--halo-shadow-soft`).
- **Empty states:** illustration, title, one line and a single Create button with a dropdown. Top customers and Top offerings have no button.

## Animations

- **Confetti** is the only animation that is not built into a component's own behaviour. Use the `Confetti` component; do not write your own:

  ```tsx
  import { Confetti, Modal } from '@chidindu06f/coachli-react';

  <Modal open={open} onClose={close} title="Session published">
    <div style={{ position: 'relative' }}>
      <Confetti />
      {/* modal content */}
    </div>
  </Modal>
  ```

  It plays once when the modal opens, is clipped at the edge of its parent and removes itself when it ends. Try it in Storybook under Components / Confetti.

## When the design system changes

You'll get a new version of the packages and a CHANGELOG entry. Update with:

```bash
npm install @chidindu06f/coachli-react@latest @chidindu06f/coachli-tokens@latest
```

Token changes (colours, fonts) need no code changes on your side. Component changes are described in the CHANGELOG.
