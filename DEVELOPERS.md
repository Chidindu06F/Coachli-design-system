# Building the Coachli dashboard

A guide for developers rebuilding the Coachli dashboard with this design system.

## What you get

| | Where |
| --- | --- |
| Components and tokens | `@chidindu06f/coachli-react` and `@chidindu06f/coachli-tokens` (install steps in the [README](README.md)) |
| Live component docs | Storybook: https://chidindu06f.github.io/Coachli-design-system/ |
| Screens to build | Figma: [Coachli](https://www.figma.com/design/toCoFh482t5Ho9OU7it9lA/Coachli), one page per menu item. Each page has grey sections per context, with black labels above each screen |
| Component specs | Figma: [COACHLI DESIGN SYSTEM](https://www.figma.com/design/fNq8x9qbF4yYA6ixgwdGVR/COACHLI-DESIGN-SYSTEM). Dev Mode shows the matching React code |

## Setup

```tsx
// main.tsx: once, at the top of the app
import '@chidindu06f/coachli-tokens/css';
import '@chidindu06f/coachli-react/styles.css';
import '@fontsource/inter/400.css';
import '@fontsource/inter/600.css';
import '@fontsource/inter/700.css';
```

- **Themes:** set `data-theme="light" | "dark" | "system"` on `<html>`. Every component switches by itself.
- **Your own CSS:** use the tokens (`var(--halo-text-secondary)`, `var(--halo-spacing-md)`), never hex values, or dark mode breaks.
- **Breakpoints:** `--halo-grid-*` tokens change at 600px (tablet), 1024px (desktop) and 1440px (wide).

## How a screen maps to code

Read a screen from its Figma layers: almost everything is a library component instance whose name matches the React component.

| In Figma | In code |
| --- | --- |
| Sidebar (Layout=Expanded / Collapsed) | `<Sidebar header={logo} beforeFooter={roleSwitch} footer={…} collapsed>` with `NavItem` children |
| Sidebar *Show footer* | `beforeFooter`: the Coach / Customer role switch (a `SegmentedControl`) |
| Sidebar *Show report a bug* / *Show log out* | `NavItem`s in `footer`. What's new and Help and resources are not in the sidebar: What's new lives in the Notifications drawer (bell); Help and resources is a row on Home, and its full page (View all) has a back arrow to Home |
| Text component (Size, Weight, Colour) | `Text` |
| Card, List, List item, Badge, Tag, Tabs, Table cells | Components with the same names |
| Modal / Drawer inside an Overlay | `Modal` / `Drawer` (they bring their own overlay) |
| Toast | `useToast()` inside a `<ToastProvider>` at the app root |
| Tour step | `Tour` |
| Plain frames | Layout only: flex/grid using the spacing tokens |

## Product rules (from design reviews)

- **Dev notes in Figma:** behaviour that a screen can't show (search timing, retention, exports) is written in a yellow **Dev note** card to the right of the screen it explains. Read them before building.

- **Page scrolling (desktop):** the dashboard is an app shell exactly the height of the window (`100vh`). The window never scrolls. The sidebar is full height; the page header (greeting, time zone, bell, Create, avatar) stays pinned at the top; only the body below it scrolls (`overflow-y: auto`), with 60px (`--halo-spacing-11`) of space after the last section. Figma shows this on *Home: scroll behaviour (prototype)*. Other screens are drawn at full height only so the whole design is visible.
- **Don't clip focus rings:** containers only clip when they scroll or truncate (e.g. the sideways Help cards, scrolling tab rows). Everything else uses `overflow: visible` so input focus rings aren't cut. The Modal body is the scroll area, so it has 4px of inner padding (the modal's sides are 20px and the header/footer sides 4px, so content still sits 24px in). Popover, Radio group, Table cell, Segmented control and Stepper slots don't clip.
- **Modals:** never taller than 720px or the window. Long content scrolls inside the modal while the title and buttons stay visible (built into `Modal` from 0.2.6).
- **Copy length:** empty-state descriptions and any helper/supporting text fit in **two lines** at most. Short, scannable sentences.
- **List alignment:** List item has **no side padding** (0 left/right, vertical padding unchanged), so rows line up with their heading, progress bar or anything else in the same container. The container holding the rows gives the inset: **12px left/right, 8px top/bottom** (the List Card style uses the same; plain list frames and mobile lists that replace tables get it too), never the row. Hover and selected backgrounds fill the row as is. `List.module.css` still uses `--pad-x` and needs updating to match.
- **Side drawers** (desktop) are **560px** wide (Drawer Size=Large).
- **Payout account (connect and update):** never a modal or sheet; the form replaces the Payout settings card inline (desktop and mobile). New coaches see **Connect bank account**; once connected the card shows the account and **Update account details**. The update form shows **Current details** (the connected account) on top; the code step shows **New details**. Steps, each revealing the next field: **Country** (Select with flag) → **Bank** (list depends on the country) → **Account number**, then **Verify details**. When verified, the field turns Success and its hint shows the account name ("Account name: JOHN DOE"), and the button becomes **Save changes**. Saving sends a 6-digit code to the coach's email (toast "Code sent to j•••@email.com") and the card becomes **Confirm your new account**: new account summary, "Wrong details? Edit" (only Edit is a link), Verification code (6), "Resend code in 0:15" countdown that turns into "Didn't get a code? Resend code", and **Verify and save** (disabled until all 6 digits). Success returns to Payout settings with the new account and a toast ("Bank account updated" / "Bank account connected"). Cancel returns to Payout settings. The Withdrawal page's Update link and the Withdraw funds modal's Change link open the same form.
- **Settings › Account & security:** two cards. **Login details** (no subtitle) lists Email and Password as rows (value underneath, secondary **Change** button). **Two-factor authentication** has the title, one line of help and a switch. When it's on, the card adds **Method** (Authenticator app or Email, Change) and, for the authenticator app only, **Recovery codes** (Regenerate). No step counters anywhere in these flows.
- **Change email / password:** Change turns the row into an inline form inside the Login details card, with no modal for the form. Email has **New email address** with Cancel / Continue; Password has **Current password**, **New password** and **Confirm new password** (EyeSlash toggles) with Cancel / Save. The primary button is disabled until the fields are filled. It then sends a code to the **current** email and opens **Check your email** ("We sent a 6-digit code to … Enter it to confirm your new email/password.") with the code input, "Didn't get a code? Resend in 0:22" then a Resend code link, and Back / Verify. Verify saves the change, closes the form and shows the toast "Email updated" / "Password updated". The Password row then reads "Last changed just now".
- **Turn on 2FA:** turning the switch on opens a modal "Turn on two-factor authentication": choose **Authenticator app** ("Recommended. …") or **Email**, shown as Radio cards (one bordered card per option, Selected state on the picked one). Next is disabled until one is picked.
  - **Authenticator app:** Next closes the modal and opens the **Authenticator app** drawer (560px; bottom sheet on mobile). It has the QR code, the setup key with Copy, and the 6-digit code input. **Verify code** is disabled until all 6 digits are in; a wrong code shows the error digits and an inline error alert. After verifying, a modal **Save your recovery codes** shows the 10 codes, "You'll only see these codes once", Download / Copy and an "I've saved my recovery codes" checkbox that enables Done. Done turns 2FA on with the toast "Two-factor authentication is on".
  - **Email:** Next opens the modal **Check your email** ("We sent a 6-digit code to …"), with the code input and "Didn't get a code? Resend in 0:22", which becomes a Resend code link when the timer ends. Back / Verify; Verify turns 2FA on with the same toast. No recovery codes.
- **Turn off 2FA:** switching it off opens **Confirm it's you** (heading "Turn off two-factor authentication", "Your account will only be protected by your password…") with the code input. Cancel / **Turn off** (destructive, disabled until 6 digits). Then the toast "Two-factor authentication is off".
- **Change 2FA method:** Method › Change opens **Confirm it's you** ("Change your two-factor method") with the code input. Cancel / Continue; Continue opens the choose-method modal titled **Change two-factor method** with the current method selected, and the setup flow runs again.
- **Regenerate recovery codes:** Recovery codes › Regenerate opens **Confirm it's you** ("Regenerate recovery codes", "Enter the code from your authenticator app to continue.") with the code input. Cancel / Continue (disabled until 6 digits). Then the modal **Save your new recovery codes** ("Your old codes no longer work…"), with the same codes, warning, Download / Copy and checkbox-gated Done as setup. Done shows the toast "New recovery codes created".
- **Settings › KYC verification** (Figma page "Settings / KYC verification"): one card, **Verify your identity**, with a two-step Stepper (Basic details › Documents).
  - **Basic details:** Full legal name (hint "As it appears on your ID."), Business name (optional), Services you offer (textarea), Social media or website (platform select + URL, **Add link**), Email address, Date of birth + Gender (side by side on desktop), Residential address, Country of residence (with flag) + Postal code, then **Next**.
  - **Documents:** four File upload dropzones, each with a one-line description: Proof of address, Government-issued ID, Selfie holding your ID, Business registration (optional). Choosing upload opens a guide modal (header icon, 3–4 short tips, Cancel / Choose file or Take selfie) before the file picker. Uploaded files show as File items (name, size, Uploaded, delete). A consent checkbox enables **Submit**; Back returns to Basic details.
  - **After submitting:** the **Submission received** modal, then the card shows an Empty state with an icon avatar: **Verification in progress** (24–48 hours, email when done), **You're verified**, or **We couldn't verify your identity** with the specific reason and **Try again**. Try again reopens the filled form with an error alert giving the reason. On mobile the same screens stack, and modals are bottom sheets.
- **Image upload** (DS, File upload page; not in the React package yet): a compact control for profile pictures and logos. An Avatar (64px Default, 48px Compact) with a User (Person) or Buildings (Business) icon when empty. **Default** adds the title "Upload image" and the hint "Min 400×400px, PNG or JPEG". When empty it shows **Upload**; once uploaded, the image shows with **Remove** (destructive) and **Change** (secondary). Use Compact where space is tight (forms, mobile).
- **Message the customer:** any details view that shows a customer (review details first) has an icon-only message button (secondary, small, ChatCircleText) at the end of the customer row. It opens that customer's conversation in Messaging. Same button on desktop and mobile, and it replaces any footer "Send message" button.
- **⋮ menus are dropdowns, never sheets:** on mobile too, a ⋮ opens a Menu right under the ⋮ (aligned to its right edge), not a bottom sheet. Sheets are for forms and details only.
- **Discounts:** the Applies to cell shows a Tooltip on hover listing the offerings when it says "N offerings", and the full name when it's truncated (not for "All offerings"; desktop only). Mobile rows show only the code (semibold, with the same copy button as desktop), "% off · used / limit uses" (e.g. "20% off · 9 / 50 uses"), the status and ⋮; offerings and dates live in the details. The Active switch has no description. Usage history tables are paginated (10 per page).
- **Payout history row menu:** the ⋮ on each row (desktop and mobile) opens View details (Payout details drawer on desktop, bottom sheet on mobile) and Copy reference.
- **Grouping:** a section's heading, its actions and its content (table or list) live in one container with a tight gap (12–16px); sections are separated by the larger page gap. Table actions (count, search, Export CSV) sit in one Table toolbar directly above the table, as on Contacts and Sales and insights.
- **Mobile keeps every action:** a row with a ⋮ menu on desktop has a ⋮ on mobile too, and a menu always opens from a visible ⋮ (or the button/field that triggers it).
- **Tabs:** tabs that filter content (All / Unread, Local / Foreign currency, Upcoming events) are **Pill, Medium** on desktop and mobile. **Line** tabs are only for switching between sub-pages (Payout: Withdrawal / Payout settings / Transaction fee settings). On mobile, Line tabs that don't fit scroll sideways (labels stay as on desktop), and the selected tab scrolls into view. When a tab holds a list, show how many items it has with the tab's count badge (Upcoming events: All 5 / Sessions 3 / Live events 2; 1:1 sessions: Upcoming 4 / Past 3; Notifications: All / Activity / What's new; Help: All / Videos / Articles; Discounts: All 6 / Active 3 / Expired 2 / Inactive 1). Counts are totals and do not change while searching.
- **Toasts:** title only (for example "Bug report sent", "Time zone updated"), shown at the **top centre**. No body text unless a design shows one.
- **Dropdowns and popovers:** no arrow, soft shadow (`--halo-shadow-soft`).
- **Empty states:** illustration, title, one line and a single Create button with a dropdown. Top customers and Top offerings have no button.
- **Event types:** neutral soft badges with a coloured dot (Session, Live event). 1:1 sessions and bundles are both "Session"; a bundle shows "Session 2 of 4" in its details.
- **Service orders:** statuses are Completed, Dispute opened, Delivered, Refunded and Cancelled.
- **Offerings in tables and lists:** show the offering's **cover image** as a rounded thumbnail before its name (36px in tables, 40px in lists, 8px radius), not a type icon. In tables, use a `TableCell` with custom content.
- **Missing images:** wherever a coach hasn't uploaded an image (offering or event cover, product image, thumbnail), show `<ImagePlaceholder>` with the closest `ratio`. Use `small-pattern` or `small-logo` under about 80px. Never leave an empty box.
- **Product tour:** 7 steps with the `Tour` component: setup checklist, Create, time zone, notifications, public profile, Help (desktop) or Menu (mobile), Report a bug. It starts on first login; Skip or Done ends it.

## Mobile (390 px designs)

- **No bottom navigation.** The top bar has a menu button on the left, then Create, the bell and the avatar. It stays fixed while the page scrolls.
- The menu opens a **left Drawer** with the logo, the full navigation (groups expand in place), the role switch, Report a bug and Log out. What's new is in the Notifications sheet (bell in the top bar); Help and resources is a row on Home.
- Notifications, Create, Account, Time zone and Report a bug open as **bottom Drawers** (sheets). Long forms scroll, and their buttons stay pinned at the bottom.
- The Top offerings table becomes a list. Event rows drop the View button and keep the ⋮ menu.

## When the design system changes

You'll get a new version of the packages and a CHANGELOG entry. Update with:

```bash
npm install @chidindu06f/coachli-react@latest @chidindu06f/coachli-tokens@latest
```

Token changes (colours, fonts) need no code changes on your side. Component changes are described in the CHANGELOG.
